# PJ1-200: Bun 1.4 アップグレードメモ

## 採用バージョン

| 項目 | 版 |
| --- | --- |
| Bun | `1.4.0` |
| @types/bun | `^1.4.0` |

`mise.toml` と `package.json` の `packageManager` で一致させる。

## 背景

Bun 1.4 は Rust 移植初版。Node.js 互換性向上（Vitest / Playwright 等）、アイドル時 CPU・メモリ削減、Next.js App Router SSR のメモリリーク修正などが含まれる。PJ1-199 認証 API 実装の前にランタイムを揃える。

## 変更範囲

- `mise.toml` / `package.json`（`packageManager`, `@types/bun`）
- `doc/PJ1-197_bun-mise-migration.md` の版数更新

`bun.lock` は依存追加がないため原則そのまま。再生成する場合は PJ1-197 の注意（`node_modules/.bin` 不整合）に従う。

## 検証コマンド

```bash
mise install
bun --version   # 1.4.0
bun install
bun run typecheck
bun run test
bun run build
```

## 既知の注意点

- メジャー相当のアップのため、不具合時は `1.3.14` へロールバック可能
- `@types/bun@1.4.0` はリリース直後に npm 反映が遅れた事例あり（現行は公開済み）

## トラブルシュート（`bun dev` で HMR / Instant validation エラー）

### 症状

```
⚠ Mismatching @next/swc version, detected: 16.2.12 while Next.js is on 16.3.0
[Server HMR] TypeError: binding.projectAllHmrEvents is not a function
[browser] Invariant: Instant validation boundaries should never appear in browser bundles
```

### 原因

Next.js 16.3 と `@next/swc` の optional 依存の版がずれている。Apple Silicon で **x64（Rosetta）の Bun** を使うと `@next/swc-darwin-x64` が古いまま残ることがある。

加えて `~/.bun/bin/bun`（単体インストール）と `mise` の Bun が混在すると、版・アーキテクチャが食い違う。

### 対処

```bash
# 1. 開発サーバーを止める（基本は Ctrl+C）
# 必要な場合のみ、対象プロセスの PID/ポートを確認して停止する
pkill -f "next dev"  # 注意: 他の next dev も停止する可能性あり

# 2. mise を有効化（新しいターミナルで bun が見つからない場合）
eval "$(mise activate zsh)"
mise install
bun --version   # 1.4.0 であること

# 3. optional 依存を揃えてキャッシュをクリア
mise exec -- bun install
rm -rf .next

# 4. 再起動
bun run dev
```

`@next/swc-darwin-x64` がまだ `16.2.12` のときは、一度削除してから `mise exec -- bun install` する。

```bash
rm -rf node_modules/@next/swc-darwin-x64
mise exec -- bun install
head -3 node_modules/@next/swc-darwin-x64/package.json   # 16.3.0 であること
```

### Apple Silicon での推奨

- 可能なら **arm64 の Bun** を使う（Rosetta 経由の x64 Bun は遅く、swc の取り違えが起きやすい）
- `which bun` が `~/.bun/bin/bun`（旧 1.3.14）を指している場合は、mise 側に寄せる
