# Firestoreデータ同期機能の追加

## 概要

1分メモアプリに、Firebase Firestoreを利用した手動データ同期機能を追加する。

同期は設定画面から手動で実行する。
同期対象はメモデータだけでなく、テーマ関連データも含める。

複数端末での利用を想定し、ローカルのIndexedDBに保存されているデータと、Firestore上のクラウドデータを差分同期できるようにする。

## 背景

現在、1分メモアプリのデータはブラウザのIndexedDBに保存されている。
今後、複数端末で同じメモ・テーマ設定を利用できるようにするため、ログイン済みユーザー向けにクラウド同期機能を追加する。

メモデータは追加されていくのみで、更新・削除は発生しない前提とする。

テーマについては、少なくとも以下の情報を同期対象とする。

- ユーザーが自身で追加したテーマ
- ランダム選択対象外にしたテーマ
- テーマに関するユーザー個別設定

## 対応範囲

- 設定画面への手動同期機能の追加
- 現在IndexedDBに保存している項目をもとにしたFirestore同期用データ構造の作成
- ログイン済みユーザーごとのデータ保存
- IndexedDBとFirestore間の差分同期
- メモデータのアップロード・ダウンロード
- テーマ関連データのアップロード・ダウンロード
- 前回同期時刻の表示
- 前回同期時刻のローカル保存
- 前回同期時刻のクラウド保存
- ローカルとクラウドの前回同期時刻差分の検知
- 同期中・同期成功・同期失敗の状態表示
- 未ログイン時は同期機能を利用できない状態にする

## 対応しない範囲

- 自動同期
- リアルタイム同期
- メモデータの更新同期
- メモデータの削除同期
- 高度な競合解決UI
- 他ユーザーとのデータ共有
- ログイン・サインアップ機能の実装
- Firebase Storageを利用したファイルバックアップ

## 前提条件

- Firebaseログイン・サインアップ機能が実装済みであること
- ログイン済みユーザーのUIDを取得できること
- 既存データはIndexedDBに保存されていること
- メモデータは追加のみで、更新・削除は行わないこと
- 各メモには端末間で一意に判定できるIDが存在する、または本チケットで追加すること
- テーマ関連データにも端末間で一意に判定できるキーが存在する、または本チケットで追加すること

## 実装方針

### IndexedDB構造の確認

実装前に、現在IndexedDBに保存しているデータ構造を確認すること。

以下を確認した上で実装する。

- IndexedDBのDB名
- IndexedDBのバージョン
- object store一覧
- 各object storeのkeyPath
- 各object storeのindex
- 各object storeに保存されているデータ項目
- メモデータの保存形式
- テーマ関連データの保存形式
- ランダム選択対象外テーマの保存形式
- ユーザー追加テーマの保存形式

### Firestore同期用データ構造の作成

現在IndexedDBに登録している項目をもとに、実装時にFirestore用のコレクション・ドキュメント構造を作成する。

下の方針でデータ構造を作成する。

- IndexedDBの既存データ項目を欠落なく保存できること
- ログインユーザーごとにデータを分離できること
- 端末間で同一データを判定できる一意キーを持つこと
- 同じデータを複数回同期しても重複しないこと
- メモデータ、テーマ関連データ、同期状態を保存できること
- Firebase Security Rulesで本人のデータのみ操作できること
- 将来的に項目が増えても拡張しやすいこと

### Firestoreデータ構造の想定

Firestoreでは、ユーザーUID配下に同期対象データを保存する。

例：

users/{uid}/memos/{memoId}
users/{uid}/themes/{themeId}
users/{uid}/themeSettings/{settingId}
users/{uid}/syncState/main

または、実際のIndexedDB構造に合わせて以下のように調整する。

users/{uid}/syncItems/{itemId}

各ドキュメントには、必要に応じて以下を持たせる。

- id
- type
- localId
- data
- createdAt
- updatedAt
- syncedAt
- deviceId
- appVersion

### データ構造作成時の注意

既存IndexedDBの項目名・型・保存単位を確認し、それに合わせてFirestore側の構造を決めること。

必要に応じて以下のどちらか、または組み合わせで設計する。

- IndexedDBのobject storeに近い形でFirestoreコレクションを分ける
- 可変項目が多いデータはdataフィールドにオブジェクト形式で保存する

ただし、以下は必ず満たすこと。

- Firestore上の各同期データはログイン済みユーザーのUID配下に保存する
- 各同期データにはIndexedDB側の一意キー、または同期用に追加した一意キーを持たせる
- ドキュメントIDには同期用一意キーを利用し、重複登録を防止する
- 前回同期時刻はユーザー単位でクラウドに保存する
- Firebase Security Rulesを設定し、他ユーザーのデータを取得・追加・更新できないようにする

## 想定仕様

### 同期の実行場所

- データ同期は設定画面から手動で実行する
- 設定画面に同期ボタンを表示する
- ログイン済みの場合のみ同期ボタンを有効にする
- 未ログイン時は同期ボタンを非表示、または無効化する
- 同期中は同期ボタンを連続実行できないようにする

### 前回同期時刻

設定画面に前回同期時刻を表示する。

- 初回同期前は - を表示する
- 同期成功時にローカルの前回同期時刻を更新する
- 同期成功時にFirestore上の前回同期時刻も更新する
- ローカルとクラウドの前回同期時刻を比較できるようにする
- ローカルとクラウドの前回同期時刻に差分がある場合、他の端末で同期された可能性があることを示す

表示例：

```text
前回同期: -
```

```text
前回同期: 2026-06-18 21:30
```

```text
前回同期: 2026-06-18 21:30
他の端末で同期された可能性があります
```

### 同期方式

同期処理は、ローカルとクラウドの双方向差分同期とする。

同期実行時に以下を行う。

1. ログイン状態を確認する
2. IndexedDBから同期対象データを取得する
3. Firestoreからログインユーザーの同期対象データを取得する
4. ローカルにのみ存在するデータをFirestoreへ追加する
5. Firestoreにのみ存在するデータをIndexedDBへ追加する
6. 同期成功時にローカルとクラウドの前回同期時刻を更新する
7. 同期結果を設定画面に表示する

### 同期対象データ

同期対象は、現在IndexedDBに保存されている以下のデータとする。

- メモデータ
- ユーザーが追加したテーマ
- ランダム選択対象外にしたテーマ
- テーマに関するユーザー個別設定
- 前回同期時刻

実装時には、IndexedDBの実データ構造を確認し、上記に該当するobject storeまたは項目を同期対象に含めること。

### メモ同期ルール

- メモは追加のみとする
- 更新・削除は同期対象外とする
- 同じメモを二重登録しない
- ローカルにのみ存在するメモはFirestoreへ追加する
- Firestoreにのみ存在するメモはIndexedDBへ追加する
- ローカルとFirestoreの両方に存在するメモは何もしない

### テーマ同期ルール

- ユーザーが追加したテーマを同期する
- ランダム選択対象外にしたテーマ情報を同期する
- テーマに関するユーザー個別設定を同期する
- 同じテーマ関連データを二重登録しない
- ローカルにのみ存在するテーマ関連データはFirestoreへ追加する
- Firestoreにのみ存在するテーマ関連データはIndexedDBへ追加する
- ランダム選択対象外の状態は、端末間で同じ状態になるように同期する
- テーマ設定のように更新が発生する可能性があるデータは、updatedAtを比較して新しい状態を優先する

### 複数端末利用時の想定シナリオ

#### シナリオ1: 端末Aで追加したメモを端末Bに取り込む

1. 端末Aでメモを追加する
2. 端末Aの設定画面でデータ同期を実行する
3. 端末AのメモがFirestoreへアップロードされる
4. 端末Aの前回同期時刻がローカル・クラウドの両方で更新される
5. 端末Bの設定画面でデータ同期を実行する
6. 端末BのIndexedDBへ、端末Aで追加したメモがダウンロードされる
7. 端末Bの前回同期時刻がローカル・クラウドの両方で更新される

#### シナリオ2: 端末A・端末Bでそれぞれメモ追加後に同期する

1. 端末Aでメモを追加する
2. 端末Bでメモを追加する
3. 端末Aの設定画面でデータ同期を実行する
4. 端末AのメモがFirestoreへアップロードされる
5. Firestore上にある端末B由来の未取得メモがあれば、端末Aへダウンロードされる
6. 端末Bの設定画面でデータ同期を実行する
7. 端末BのメモがFirestoreへアップロードされる
8. Firestore上にある端末A由来の未取得メモが端末Bへダウンロードされる
9. 最終的に端末A・端末B・Firestoreのメモが同じ状態になる

#### シナリオ3: 端末Aでテーマを追加し、端末Bに取り込む

1. 端末Aでユーザー追加テーマを作成する
2. 端末Aの設定画面でデータ同期を実行する
3. 端末AのテーマがFirestoreへアップロードされる
4. 端末Bの設定画面でデータ同期を実行する
5. 端末Bに端末Aで追加したテーマが追加される

#### シナリオ4: 他端末で同期済みであることを検知する

1. 端末Aでデータ同期を実行する
2. Firestore上の前回同期時刻が更新される
3. 端末Bで設定画面を開く
4. 端末Bのローカル前回同期時刻とFirestore上の前回同期時刻に差分がある
5. 他の端末で同期された可能性があることを表示する

## セキュリティ

Firebase Security Rulesを設定し、ログインユーザー本人のデータのみ操作できるようにする。

Firestoreの同期用コレクションに対して以下を必ず設定する。

- ログイン済みユーザーのみアクセスできる
- ログインユーザー本人のUID配下のデータのみreadできる
- ログインユーザー本人のUID配下のデータのみcreateできる
- テーマ設定や同期状態など更新が必要なデータは、ログインユーザー本人のUID配下のデータのみupdateできる
- 他ユーザーのデータを取得・追加・更新・削除できない

Security Rulesの考え方：

users/{uid}/...

に対して、request.auth.uid == uid の場合のみアクセスを許可する。

## 画面・UI

設定画面に以下を追加する。

- データ同期ボタン
- 前回同期時刻
- 同期状態メッセージ
- 同期結果表示

表示する同期結果の例：

- アップロードしたメモ件数
- ダウンロードしたメモ件数
- アップロードしたテーマ関連データ件数
- ダウンロードしたテーマ関連データ件数
- 更新したテーマ設定件数
- 同期完了日時

未ログイン時の表示例：

```text
データ同期を利用するにはログインしてください
```

初回同期前の表示例：

```text
前回同期: -
```

同期成功時の表示例：

```text
同期が完了しました
前回同期: 2026-06-18 21:30
```

他端末同期検知時の表示例：

```text
他の端末で同期された可能性があります。最新データを取り込むには同期してください。
```

## エラーハンドリング

- 未ログイン時に同期しようとした場合は、ログインが必要であることを表示する
- Firestoreへの接続に失敗した場合は、同期失敗として表示する
- 一部データのアップロードに失敗した場合は、可能であれば失敗件数を表示する
- 一部データのダウンロードに失敗した場合は、可能であれば失敗件数を表示する
- 同期失敗時も、既存のローカルデータは削除しない
- 重複登録エラーは同期処理全体の失敗扱いにしない
- Firestoreの権限エラーが発生した場合は、再ログインまたは権限設定の確認が必要であることを表示する

## 実装メモ

- 実装前に必ずIndexedDBの既存構造を確認する
- Firestore側のデータ設計は、IndexedDBに保存している実項目から生成する
- 同期処理は設定画面の手動操作でのみ実行する
- 同期処理は「アップロード」と「ダウンロード」の両方を1回の同期操作で実行する
- 差分判定には、IndexedDB側の一意キーまたは同期用に追加した一意キーを利用する
- Firestore側ではドキュメントIDに同期用一意キーを利用し、同一データの重複登録を防止する
- メモのアップロード時は setDoc を利用し、同一ドキュメントIDの場合は重複作成されないようにする
- テーマ設定のように変更される可能性があるデータは、updatedAtを確認して新しい状態を優先する
- ダウンロード時は、ローカルに存在しないデータのみIndexedDBへ追加する
- テーマ設定のように更新が必要なデータは、ローカルとFirestoreの更新日時を比較して反映する
- 同期処理中は二重実行を防止する
- ログアウト時にローカルデータは削除しない
- 前回同期時刻はローカルとFirestoreの両方に保持する
- Firestoreの書き込みは必要に応じて writeBatch を利用する
- Firestoreの取得件数が増える可能性があるため、将来的にはupdatedAtやsyncedAtによる差分取得も検討できるようにする
- 将来的な自動同期やリアルタイム同期には拡張できるようにするが、本チケットでは手動同期のみ実装する

## 備考

本チケットでは、設定画面から実行する手動同期機能を実装する。
同期対象はメモデータ、ユーザー追加テーマ、ランダム選択対象外テーマ設定、テーマに関するユーザー個別設定とする。

Firestore側の固定的なデータ設計はこのチケットでは指定しない。
実装時に、現在IndexedDBに保存されている項目を確認し、それをもとに同期用のコレクション・ドキュメント構造を作成する。

自動同期、リアルタイム同期、メモの更新・削除同期、高度な競合解決UIは対象外とする。
