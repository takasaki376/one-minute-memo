## タイトル

認証・同期API I/F設計と実装方針確定（API Route主軸）

## 種別

Task

## 背景

- Firebase認証処理がクライアント側にあり、認証ロジック・セッション管理をサーバー側へ移行したい。
- Firestore同期処理（読み込み・更新）もクライアント側で実行されており、同様にAPI Route経由へ移行したい。
- 後続実装の手戻り防止のため、先に認証と同期のAPI契約を確定する必要がある。

## 目的

- API Routeベースの認証・同期I/Fを確定する。
- リクエスト/レスポンス、エラー形式、セッションCookie仕様、同期データ契約を統一する。

## スコープ

- 認証APIエンドポイント仕様定義
- 同期APIエンドポイント仕様定義
- 型定義（認証/同期レスポンス、エラー、ユーザーサマリー）
- エラーコードとメッセージ方針
- httpOnly Cookie仕様
- 同期データ契約と競合解決方針

## 対応内容

1. 認証API契約定義

- POST /api/auth/signup
- POST /api/auth/signin
- POST /api/auth/signout
- GET /api/auth/session

2. 同期API契約定義

- POST /api/sync/upload
- POST /api/sync/pull
- GET /api/sync/state
- POST /api/sync/run（upload + pull の一括実行）

3. 共通レスポンス形式

- 成功: { success: true, data: ... }
- 失敗: { success: false, error: { code: string, message: string } }

4. セッション仕様

- Cookie: httpOnly, sameSite=lax(or strict), secure(本番), maxAge定義

5. 型定義

- AuthResponse, AuthErrorResponse, SessionUser
- SyncResponse, SyncErrorResponse, SyncPayload

6. 同期データ契約と競合解決

- 同期対象: memos, sessions, themes, themeSettings, syncState
- 競合解決方針: updatedAt優先、差分未確定時はサーバー値優先

7. 既存エラーメッセージとの整合

- Firebaseエラーコードと日本語メッセージの対応表を確定

## 完了条件（Acceptance Criteria）

- 認証・同期API I/F仕様が文書化されている
- 後続タスクが参照可能な型定義とエラー契約がある
- セッションCookie方針が確定している
- 同期データ契約と競合解決ルールが確定している

## 想定リスク

- I/F曖昧さによる後続手戻り
- エラー契約の不一致
- 同期対象データの契約漏れ
