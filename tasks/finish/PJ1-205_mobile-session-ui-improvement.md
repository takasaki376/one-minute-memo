## 2. スマホの初期入力モード

1. スマホでセッションを開始したとき、テキスト入力タブを選択して入力欄を表示する。画面幅の判定前に手書きが操作可能な状態で一瞬表示されることを避ける。
2. 手書き／テキストをユーザーが選択した後は、次テーマへの移動でも選択を維持する。キーボード開閉による高さ変化や再描画でテキストへ戻さない。
3. タブ切替で入力済みの本文・筆跡を保持する。既存の {{useSessionFlow}} を通じた保存・次テーマ遷移・完了画面への遷移を維持する。
4. 画面回転や {{767px}}／{{768px}} をまたぐ幅変更でも入力内容を保持する。スマホへ移行した場合も、ユーザーが選択済みの入力モードを不用意に上書きしない。
5. 既存の {{TextEditor}} の {{autoFocus}} と日本語IME入力を確認する。初期選択でキーボードが表示される場合も、テーマ・残り秒数・入力カーソルを確認できるようにする。

## 3. 入力切替と操作ボタンの一行配置

1. スマホでは、左端に「手書き入力」「テキスト入力」、右端に一時停止／再開と次へを配置し、同じ行に収める。
2. 左側の入力切替はテキストラベルを維持する。右側は一時停止・再開・次へを判別できるアイコンボタンにし、長い表示ラベルによる横幅を削減する。
3. {{isRunning}} に応じて一時停止と再開のアイコン・アクセシブル名を切り替える。次へ操作のアクセシブル名は「このテーマを終えて次へ」とする。アイコン自体には {{aria-hidden}} を指定する。
4. 既存の {{pause}}、{{start}}、{{handleThemeFinished}} と {{secondsLeft === 0}} の無効化条件を利用する。最終テーマでは既存の保存・セッション完了処理につなぐ。
5. 状態表示「入力中…」「一時停止中」が一行配置を圧迫する場合は配置を調整する。一時停止中であることはアイコンやアクセシブル名からも判断できるようにする。
6. {{320px}} 幅でも一行を維持できるよう、入力切替の余白・文字サイズ・グループ間隔を調整する。アイコンの見た目を小さくしつつ、タップ領域は原則 {{44 × 44 CSS px}} を確保する。
7. 入力タブの {{role}}、{{aria-selected}}、{{aria-controls}} とパネルの関連付け、フォーカス表示を維持する。既存のボタンやアイコン表現を優先して利用する。

## 4. スマホの手書きペンを「細」にする

1. スマホで手書き入力に切り替えたとき、ペンの線幅に既存の {{s}}（細）を適用する。
2. スマホでは「細・中・太」の切替UIを省略する。ペン、消しゴム、クリアは引き続き操作できるようにする。
3. {{HandwritingToolbar}} と {{useHandwritingCanvasEngine}} の状態連携を確認し、UIの非表示と実際の描画線幅を一致させる。スマホへ幅変更した場合も細で描けるようにする。
4. 既存の線幅定義を再利用し、保存済みの筆跡は元の見た目で保持する。回転・幅変更・入力切替で筆跡を消さない。
5. PC・iPadの太さ選択と手書き集中モードの既存動作を維持する。スマホの細固定が共有コンポーネント経由で他の表示幅へ波及しないようにする。

## 5. テーマ・残り秒数の上部固定

1. スマホのセッション中は、テーマ本文と残り秒数を含む領域を画面上部へ固定し、ページをスクロールしても両方を表示する。
2. 共通ヘッダー {{src/components/ui/Header.tsx}} は通常のスクロールで画面外へ移動できる構成にする。テーマ領域が上端に達した後は上部に留まるよう、{{sticky}} と {{top}} を用いた構成を第一候補に検討する。
3. 固定領域の祖先が短いセクションに限定されると、その末尾で固定が解除されるため、入力欄を含むセッション全体をスクロールしても固定が継続する構造にする。祖先の {{overflow}} 指定も確認する。
4. テーマは省略記号で切らず、長い本文を折り返して表示する。秒数と重ならず、背景・重なり順を設定して入力本文が透けないようにする。
5. 入力切替・操作行はテーマと秒数の直下へ配置する。固定領域へ含める場合は、その高さも含めて入力欄とキーボード表示時の可視領域を確認する。
6. ページ末尾、テーマ切替後、一時停止中、キーボード表示中もテーマ・残り秒数を確認できることを確認する。固定領域によって入力欄やフォーカス中のカーソルが隠れる場合はスクロール余白を調整する。
7. ブラウザのアドレスバー伸縮、端末のセーフエリア、スマホ横向き、文字拡大時の重なりを確認する。

## 6. 回帰防止・動作確認

1. {{320 × 568}}、{{375 × 667}}、{{390 × 844}}、{{430 × 932 CSS px}} で、テキスト初期表示、操作の一行配置、テーマ・残り秒数の固定を確認する。ページ末尾までスクロールし、固定が途中で解除されないことを確認する。
2. 長いテーマ、ライト／ダークモード、文字拡大、ソフトウェアキーボードの開閉、日本語IME変換中を確認する。横はみ出しを {{document.documentElement.scrollWidth}} と {{clientWidth}} でも検証する。
3. テキスト入力→一時停止→再開→次テーマ→最終テーマ完了→履歴表示を確認する。手書きへの切替→細で描画→消しゴム→テキストへの切替→手書きへ戻る→保存も確認する。
4. スマホ横向き、{{767px}}／{{768px}} 境界、iPad横向き {{1024 × 768}}・{{1180 × 820}}、PC {{1440 × 900 CSS px}} で、入力内容の保持と既存レイアウト・集中モードの回帰を確認する。
5. {{e2e/mobile-layout.spec.ts}}、{{e2e/session.spec.ts}}、関連する既存テストを確認し、初期タブ、アイコンの名前・操作、スマホの細適用、スクロール固定を検証するケースを追加・更新する。
6. {{bun run lint}}、{{bun run typecheck}}、{{bun run test}}、{{bun run build}}、関連する {{bun run test:e2e}} を実行する。表示確認のスクリーンショットと結果を実装報告に残す。
7. iPhone Safari・Android Chromeでキーボード表示中の固定領域と入力操作を確認する。実機未確認の項目は、エミュレーション結果と併せて記録する。
