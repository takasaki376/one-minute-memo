## タイトル

テスト実行基盤のBun移行とテストコード再編（Bun + Vitestハイブリッド運用）

## 種別

Task

## 背景

- 実行環境をBunへ寄せる方針に合わせ、テスト実行もBun中心へ移行したい。
- ただし、Bunで実行できないテスト（互換性・モック差分・DOM依存など）はVitestで継続実行する必要がある。
- 既存の test コマンド実行時に、Bun側とVitest側の両テストを一括で回せる状態を作りたい。

## 目的

- テストコードをBun対応前提で再編・必要箇所を書き換える。
- Bun非対応テストはVitestに明確に分離し、確実に実行する。
- bun run test 1回で、BunテストとVitestテストの両方が実行される運用を確立する。

## スコープ

- テストコードの書き換え・再配置
- テストランナーの分離設計（Bun / Vitest）
- package scripts の再設計
- ドキュメント更新
- 回帰確認（unit / component / e2eの影響確認）

## 対応内容

1. テスト分類と実行方針策定

- 既存テストを「Bun実行可能」「Vitest継続」の2区分に分類
- 分類基準を定義（例: DOM依存、JSDOM依存、特定モック依存、API差分）
- テスト配置/命名規約を決定
- 例: Bun用は _.bun.test.ts、Vitest用は _.test.ts / \*.test.tsx など

2. テストコード書き換え（本チケット対象）

- Bun移行可能なテストは bun test で通る形に修正
- 互換差分（モック・タイマー・環境APIなど）を吸収するためのリファクタを実施
- Bun非対応テストはVitest実行前提で必要最小限の修正に留める

3. 実行コマンド整備

- scripts を以下方針で整備
- test:bun: Bunランナー対象テストを実行
- test:vitest: Vitest対象テストを実行
- test: bun run test:bun && bun run test:vitest
- bun run test 実行時に必ず両方走ることを保証

4. 設定ファイル更新

- Bunテスト対象のinclude/exclude設定を追加（必要ならbunfig.toml等）
- Vitest側のinclude/excludeを再定義し、重複実行を防止
- PlaywrightやE2E導線に影響があれば設定を追随更新

5. ドキュメント更新

- READMEのテスト実行手順を更新
- 「Bunで実行するテスト」と「Vitestで実行するテスト」の境界を明記
- 新規テスト追加時のルール（どちらに書くか）を明文化

6. 検証

- bun run test が成功し、Bun + Vitest両方の結果が取得できる
- bun run test:bun 単体成功
- bun run test:vitest 単体成功
- 既存主要機能に関する回帰確認を実施

## 非スコープ

- テストコードの全面リライト
- テストフレームワークの変更（Vitest -> 別FW など）
- テストケース追加・削除の大規模見直し

## 完了条件（Acceptance Criteria）

- テストコード書き換えが完了し、分類方針に従って再編されている
- Bun非対応テストはVitest実行経路に確実に残っている
- bun run test で BunテストとVitestテストが順次実行される
- テスト重複実行や取りこぼしがない（対象一覧と実行ログで確認）
- READMEに運用ルールと実行方法が反映されている

## 想定リスク

- BunとVitestの挙動差分で断続的な不安定テストが出る可能性
- テスト分類漏れにより未実行テストが発生する可能性
- ランナー二重化により保守コストが一時的に増加する可能性

## 優先度

High

- テスト分類・方針策定: 0.5日
- テストコード書き換え: 1.0日
- スクリプト/設定更新: 0.5日
- 検証・ドキュメント更新: 0.5日

- 運用開始後、残課題（不安定テストの恒久対策など）はフォローアップチケットで管理する。
