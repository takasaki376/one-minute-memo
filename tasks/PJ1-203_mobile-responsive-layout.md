## 1. 現状確認・対応範囲の確定

## 2. 共通ヘッダー・ナビゲーション

1. スマホ幅ではロゴと開閉ボタンを一段に配置し、ナビゲーションは開閉式にする。広い画面では既存の横並びを維持する。
2. Home・セッション・履歴・テーマ管理・設定・ログインへの到達性を維持し、ラベルが一文字ずつ改行されない幅を確保する。
3. メニューボタンに {{aria-expanded}} と {{aria-controls}} を付け、タップ・キーボードで開閉できるようにする。Escapeとリンク選択で閉じ、Escape時は開閉ボタンへフォーカスを戻す。
4. {{src/components/auth/HeaderAuthControl.tsx}} の認証状態別表示を維持する。未ログイン・ログイン済み・長いメールアドレス・読込中を確認し、ログインモーダルを妨げない。
5. 必要なクライアント状態は小さなコンポーネントに分離し、UIライブラリを追加しない。主要タップ領域は原則44×44 CSS px以上とする。

## 3. セッションの余白・情報・操作配置

1. スマホではページ余白の重複を減らし、画面端から入力面までの左右余白を合計各24px以内にする。PC・iPad横向きの余白は既存値を維持する。
2. {{src/components/session/ThemeHeader.tsx}} の進捗・カテゴリ・タイマーをスマホではコンパクトにまとめ、テーマ本文は読める形で折り返す。長いテーマやカテゴリでも操作部と重ならないようにする。
3. 手書き／テキスト切替、一時停止／再開、次テーマへのボタンをスマホ用に配置する。主要ボタンのラベルは途中で一文字ずつ折り返さず、意図した段組みで表示する。
4. 390×844 CSS px、標準文字サイズ、短いテーマの通常状態では入力面の上端が画面内に入り、少なくとも高さ240pxを初期表示で確認できることを目標とする。長文テーマ・拡大文字・短い画面では縦スクロールで全操作に到達できることを優先する。
5. 横方向のはみ出しをページ全体の {{overflow-x-hidden}} で隠して解決しない。必要な箇所の縮小・折り返し・幅制約を見直す。

## 4. 入力領域・タッチ操作

1. スマホの固定高さを見直し、可視領域に応じた高さと最低限の入力面積を両立する。ブラウザのアドレスバー、ソフトウェアキーボード、セーフエリアを考慮し、必要な縦スクロールを許容する。
2. {{src/components/session/HandwritingToolbar.tsx}} を再利用し、スマホでもペン・消しゴム・太さ・クリアを操作できる簡略配置を追加する。ツールバーは入力面外の折り返し配置を基本とし、描画やスクロールを妨げない。ペン太さの定義や消しゴム処理自体は変更しない。
3. {{src/components/session/useHandwritingCanvasEngine.ts}} の既存 {{ResizeObserver}}、DPR対応、描画保持処理を確認する。レイアウト変更だけで解決できる場合は描画エンジンを変更しない。
4. 画面回転・幅変更・入力タブ切替後に筆跡が消えず、入力位置と線が一致することを確認する。非等方な拡縮等が生じる場合は再現条件を記録し、既存の保存形式を壊さない対応を検討する。
5. {{touch-action}} の制限は描画面に限定する。描画面外でページをスクロールでき、下部の操作へ到達できることを確認する。
6. {{src/components/session/TextEditor.tsx}} は日本語IME入力、キーボード表示時のカーソル視認、タブ切替時の本文保持を確認する。入力中の画面サイズ変化でタイマーやセッションを初期化しない。
7. 既存の手書き集中モードのスマホへの新規提供は範囲外とする。{{768px}} をまたぐ回転時に既存の終了処理が働き、ポータルやダイアログが残らないことを確認する。

## 5. 回帰防止・動作確認

1. Playwrightの既存構成 {{playwright.config.ts}} と {{e2e/session.spec.ts}} を確認し、モバイル用の表示・操作確認を追加する。既定プロジェクトは現在Desktop Chromeのみのため、単なる実行だけでスマホ検証済みとしない。設定変更が必要なら変更理由と範囲を明示する。
2. 少なくとも320×568、375×667、390×844、430×932 CSS pxで、ヘッダーとセッションの横はみ出し・ラベル表示・操作到達性を確認する。{{document.documentElement.scrollWidth}} が {{clientWidth}} を超えないことを検証する。
3. スマホ横向き、767px／768pxの境界、iPad横向き1024×768・1180×820、PC1440×900で確認する。PC・iPad横向きは変更前後のスクリーンショットで配置・余白を比較する。
4. 追加するVitest／Testing Libraryテストはメニュー開閉・Escape・ナビゲーション・認証状態の動作に絞る。CSSの表示品質はブラウザで確認する。
5. 手書き入力→タブ切替→戻る→回転→保存→履歴表示、およびテキスト入力→一時停止／再開→次テーマ→完了を確認する。{{bun run lint}}、{{bun run typecheck}}、{{bun run test}}、{{bun run build}} と、関連する {{bun run test:e2e}} を実行する。実行できない検証がある場合は理由と未確認範囲を記録する。
6. iPhone Safari・Android Chrome実機で描画、スクロール、キーボード表示を確認する。実機未確認の場合はエミュレーション結果と区別し、未確認項目を記録する。ライト／ダークモードと文字拡大時も操作不能にならないことを確認する。
