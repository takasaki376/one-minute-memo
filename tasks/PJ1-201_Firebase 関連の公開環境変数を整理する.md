# PJ1-201：Firebase 関連の公開環境変数を整理する

ローカル調査用ツールが起動できなかったため、実際の変数名・参照ファイルは未確認です。以下は、API Route への移行済みという前提で作成した Jira チケット案です。

## AI に依頼する作業の範囲

- 本文の作業内容は AI への依頼事項とする。
- `.env.local` の内容の確認・編集・削除は、今回の AI 作業の対象外とする。
- ソースコードから削除対象の環境変数への参照がなくなったことを人が確認した後、`.env.local` の不要な定義は人が手動で削除する。
- 動作確認のために `.env.local` を一時的に変更することも禁止する。未設定での検証は、`.env.local` を読み込まない隔離した検証環境で行う。

---

## チケット1：Firebase 関連の公開環境変数と依存箇所を棚卸しする

**種別:** Task

**背景・目的**

Firebase の処理をサーバー側の API Route に移行したため、残存する Firebase 関連の `NEXT_PUBLIC_*` 環境変数について、削除対象とサーバー側への移行対象を確定する。

**作業内容**

- ソースコード、テスト、スクリプト、設定ファイルから Firebase 関連の `NEXT_PUBLIC_*` 参照を検索する。
- `.env.local` を除く環境変数定義、環境変数テンプレート、CI/CD、デプロイ環境の定義を確認する。記録するのは変数名と用途のみとする。
- Firebase クライアント SDK の初期化処理と呼び出し元を確認する。
- API Route 内に公開環境変数への依存や旧変数名へのフォールバックが残っていないか確認する。
- 各変数を「削除」「サーバー専用変数へ移行」「継続利用」に分類する。
- Firebase 以外の `NEXT_PUBLIC_*` は今回の削除対象から除外する。

**受け入れ条件**

- 変数名、定義場所、参照箇所、用途、対応方針の一覧が作成されている。
- クライアント側に Firebase 処理が残っている場合、その解消作業が明確になっている。
- 削除後に必要となるサーバー側設定が特定されている。

## チケット2：Firebase の公開環境変数へのコード依存を解消する

**種別:** Task  
**依存:** チケット1

**背景・目的**

Firebase 関連の公開環境変数を削除しても、認証・同期処理が API Route 経由で動作する状態にする。

**作業内容**

- 残存するクライアント側の Firebase 処理があれば、既存の API Route 経由に変更する。
- 未使用となった Firebase クライアント初期化処理、設定オブジェクト、import、補助関数を削除する。
- サーバー側で引き続き必要な設定は、`NEXT_PUBLIC_` を付けない環境変数へ移行する。
- 旧公開変数名へのフォールバックを削除する。
- クライアント側の機能判定や設定チェックを、公開 Firebase 設定に依存しない形へ変更する。
- 関連テスト・モックを更新する。
- Firebase クライアント SDK の利用が完全になくなった場合のみ、不要な依存パッケージを削除する。

**受け入れ条件**

- 削除対象の公開環境変数への実行コードの参照が残っていない。
- サーバー専用設定がクライアントから参照されていない。
- 認証・Firestore 同期は `src/app/api/**/route.ts` 経由で実行される。
- API の入出力・エラー契約が `doc/PJ1-199-01_auth-sync-api-contract.md` と整合している。

## チケット3：環境変数定義とセットアップ資料を整理する

**種別:** Task  
**依存:** チケット2

**背景・目的**

ローカル開発やデプロイで、不要な Firebase 公開環境変数を設定し続ける状態を解消する。

**作業内容**

- `.env.local` の変更は行わず、人が後から削除する変数名と確認手順を資料に記載する。
- 環境変数テンプレート、CI/CD、デプロイ環境から同じ定義を削除する。
- サーバー専用変数へ移行する場合、必要な設定を反映してから旧定義を削除する。
- README、`doc/`、セットアップ手順の変数一覧・記載例を更新する。
- チームメンバー向けに、各自のローカル設定で削除・追加する変数名を明記する。`.env.local` の不要な定義の削除は、ソースコードからの参照削除を人が確認した後に、人が実施することを記載する。
- 旧変数を含むビルド成果物が残らないよう、再ビルド・再デプロイする。

**受け入れ条件**

- `.env.local` を除く管理対象の設定・テンプレートから不要な公開変数が削除されている。
- `.env.local` が変更されておらず、人による確認・手動削除の手順が資料に記載されている。手動削除の実施は本チケットの完了条件に含めない。
- 最新の手順に従い、Firebase 関連の削除対象 `NEXT_PUBLIC_*` を設定せずに起動できる。
- サーバー側で必要な環境変数と設定方法が資料に記載されている。

## チケット4：公開環境変数削除後の回帰確認を行う

**種別:** Task  
**依存:** チケット2・3

**背景・目的**

Firebase 関連の公開環境変数が未設定でも、既存機能と API Route が正常に動作することを確認する。

**作業内容**

- `.env.local` を読み込まない隔離した検証環境で、削除対象の環境変数を設定せずに、型チェック・Lint・関連 Vitest テスト・本番ビルドを実行する。サーバー側に必要な変数は検証環境に別途設定する。
- signup、signin、signout、session の動作を確認する。
- Firestore 同期の upload、pull、state、run の動作を確認する。
- 未認証・セッション期限切れ・API エラー時の挙動を確認する。
- IndexedDB によるメモ保存、履歴表示、オフライン利用を確認する。
- ソースコードとクライアント向けビルド成果物に、削除対象の変数名・旧初期化処理が残っていないか確認する。

**受け入れ条件**

- `.env.local` を変更せず、隔離した検証環境で削除対象の公開環境変数なしのビルドと関連チェックが成功する。
- 認証・同期・ローカル保存の確認結果が記録されている。
- サーバー専用の設定値がクライアント向け成果物に含まれていない。
- 残存参照がある場合、用途と継続理由が明記されている。
